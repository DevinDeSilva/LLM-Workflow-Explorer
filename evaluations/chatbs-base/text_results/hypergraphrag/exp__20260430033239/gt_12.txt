The post‑processing stage of the pipeline is driven by the **Query Result Post‑Processor** function, which is generated by the *Query Result Post‑Processor Function Generator* (ChatBS‑NexGen:LLM‑query_result_post_processor).  This function takes as input the raw knowledge‑graph results that flow out of the batch SPARQL query extractor via its `kg_knowledge` output port, and it produces a single **output parameter** named **`post_processed_output`**.  The `post_processed_output` port is defined on the Query Result Post‑Processor program (ChatBS‑NexGen:query_result_post_processor) as its sole output, carrying the cleaned or transformed results that are then passed downstream for further consumption.
