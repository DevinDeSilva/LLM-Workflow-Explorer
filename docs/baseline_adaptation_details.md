# Baseline Adaptation Details

The ChatBS-NexGen workflow graph contains 895 RDF triples over 177 URI subjects, while the Biomni workflow graph contains 2,022 RDF triples over 230 URI subjects. Unless otherwise noted, labels are taken from `rdfs:label` and `skos:prefLabel`; descriptions from `dc:description` and `prov:definition`; and identifiers from `dcterms:identifier`.

The baselines differ in their native input requirements: GRASP operates over a SPARQL endpoint, HippoRAG expects passages and OpenIE-style facts, HyperGRAG expects chunks, entities, and hyperedges, and VSB retrieves over embedded text segments. To ensure a fair comparison, each baseline is constructed from the same underlying workflow KG, receives the same natural-language questions, and is not given any external corpus. The only difference is the representation used to adapt the KG to each baseline's expected input format.

All local LLM calls use `gpt-oss-20b` through LM Studio. Vector-based methods use `text-embedding-bge-large-en-v1.5` unless the baseline requires its own embedding index.

For text-based and graph-RAG baselines, we enumerate every URI subject in the workflow KG and construct one object-level representation per subject. Each representation includes a CURIE, a human-readable label derived from labels or identifiers, `rdf:type` values, and non-type outgoing triples rendered as property lines containing the predicate CURIE, predicate label, object CURIE when applicable, and object label or literal.

VSB embeds these object descriptions directly. HippoRAG receives the same descriptions as passages, along with an injected OpenIE file whose `extracted_entities` and `extracted_triples` are produced mechanically from the RDF triples rather than generated by an LLM. HyperGRAG receives the same descriptions as chunks; non-type RDF triples are converted into hyperedge-like records, while URI objects and literals are represented as entity nodes.

GRASP is adapted differently: instead of receiving a flattened corpus, it queries the same workflow KG through a Fuseki SPARQL endpoint and uses entity/property indices derived from labels, aliases, comments, domain/range information, observed usage, and example values where available.

The table below summarizes the native representation, graph access, and ontology/schema access provided to each baseline.

## Native Representation and Graph Access

*"Same triples" indicates whether the baseline was constructed from the same execution KG, although the retrieval-time answer context may still be a subset.*

| Method | Native input representation | Same triples as ours? | Ontology/schema access |
|---|---|---|---|
| **GWB** | An in-memory `rdflib` graph converted into entity, predicate, triple, and execution records. The LLM only rewrites an already-grounded symbolic draft. | Yes. Symbolic indices are built from the full graph. | Yes. Used to name predicates and classes. |
| **VSB** | One text segment per URI subject, listing the subject CURIE, label, RDF types, and outgoing properties with object labels or literals. | Yes. Segments are constructed from the full graph. | Partial. Ontology labels are used for predicates, but RDF domain/range semantics are not reasoned over after flattening. |
| **GRASP** | The workflow graph is exposed as a SPARQL endpoint. GRASP searches entity/property indices and iteratively generates and executes SPARQL. | Yes. The SPARQL endpoint is loaded with the same workflow graph. | Partial. GRASP receives prefixes and queryable labels, comments, domain/range, and type information from the endpoint/index. It does not receive our generated SQ Library. |
| **HippoRAG** | The KG is converted to one passage per URI subject plus an injected OpenIE file. ChatBS-NexGen produces 177 passages and Biomni produces 230 passages; the injected OpenIE contains 895 ChatBS-NexGen triples and 2,022 Biomni triples. | Yes. Triples are mechanically flattened into passage text and injected OpenIE triples. | Partial. Ontology labels are used during conversion, but HippoRAG receives passages/OpenIE facts rather than the formal ontology schema. |
| **HyperGRAG** | The same per-subject KG passages are converted into HyperGraphRAG chunks, entities, and hyperedges. ChatBS-NexGen yields 177 chunks, 345 entities, and 718 hyperedges; Biomni yields 230 chunks, 1,169 entities, and 1,792 hyperedges. | Mostly. Ontology labels are used during conversion, but HyperGRAG receives a flattened hypergraph rather than RDF/OWL semantics. |
